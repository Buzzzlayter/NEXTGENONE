# NEXTGENONE

Игровой модуль проекта. Здесь находятся правила игры, способности, персонажи, Combat, экипировка, интеракция и AI. Модуль связывает [GameplayFoundation](../GameplayFoundation/ARCHITECTURE.md), [UIModule](../UIModule/ARCHITECTURE.md), ALS и навигацию. Gameplay код группируется по подсистемам, include пути начинаются от корня модуля, классы способностей находятся в `Gameplay/Abilities`.

Перед изменениями прочитай [общие правила работы с проектом](../../Docs/WorkingAgreement.md).

## Владение игровым состоянием

- Основная цепочка использует `ANextgenoneGameMode`, `ANextgenonePlayerController`, `ANextgenonePlayerState` и `ANextgenoneCharacter`. PlayerState владеет ASC и HealthSet. Pawn выступает текущим Avatar. Доступ к ASC идёт через `IAbilitySystemInterface` или геттер.
- Controller владеет управлением. Здоровье, инвентарь, интеракция и способности принадлежат выделенным владельцам. Для общего кода использовать базовые типы и узкие интерфейсы.
- У каждого состояния один владелец. Он проверяет готовность, актуальность установки и учёт ресурсов. Изменения идут через его API. Производные значения вычисляются из исходного состояния.
- Управляющий компонент обращается к своим объектам данных и визуала. Обратные зависимости через `Owner`, `Outer`, поиск компонента, геттер или вызов из RepNotify не допускаются. Объект сообщает об изменении своих данных, потребитель управляет подпиской.

## FSM, GAS и сеть

- Character FSM на Pawn Blueprint управляет состояниями персонажа и временем жизни ресурсов. `UNGControlStateDefinition` задаёт способности, эффекты и IMC. Выдача и снятие идут по handles источника. Базовые способности выдаёт состояние.
- UI FSM управляет интерфейсом отдельно. Готовность персонажа, GAS и репликации проверяется до использования игроком игровых систем. Тег `Alive` сам по себе не подтверждает готовность. Gameplay и UI IMC принадлежат соответствующим FSM. Controller не хранит флаги открытых окон для блокировки gameplay.
- Учитывать possession, `OnRep_PlayerState`, UnPossess и смену жизни. Старый Pawn, снаряды и callbacks не должны менять новую жизнь. Дублирующие выдачи ресурсов не допускаются.
- Сервер авторитетен для урона, выстрелов, экипировки, переноса предметов и доступа к контейнерам. Проверять параметры RPC. Постоянные ограничения частоты хранить у владельца, который переживает переэкипировку и повторную активацию способности.
- ALS отвечает за locomotion, mantle и ragdoll. Смерть проходит через `Dead` → `GA_Death` → ALS ragdoll, поза тела локальна. При изменениях ALS учитывать контракт authority.

## Инвентарь, экипировка и AI

- `UNGPlayerInventoryManagerComponent` на PlayerState принимает RPC и владеет сессией доступа к хранилищу. Его базовый `UNGInventoryManagerComponent` исполняет операции над предметами. Интеракция общая для предметов и контейнеров.
- Экипировка связывается с предметом через equipment fragment. Предмет активирует подходящую GAS способность. Экипировка использует существующие предметы, а тестовая выдача не относится к штатному потоку. UI получает данные через `UNGInventoryPanel`, вместо прямых обращений из слотов к Pawn.
- Серверный `ANGAIController` управляет поведением и выполняет действия через те же способности и системы персонажа. AI FSM исполняет шаги восприятия и перемещения, EQS выбирает позиции, NavMesh отвечает за наземные маршруты.
