# EQS в AI-графе

`NGAIQueryState` запускает запрос асинхронно на сервере. Используется существующий `AIModule`; Blackboard и новые подсистемы не добавляются. Querier — текущий Pawn бота, а не контроллер или объект поведения.

## Настройка

После пользовательской сборки C++ в Behavior Blueprint добавить FSM State с Implementation Class = `NGAIQueryState`.

| Поле | Назначение |
| --- | --- |
| QueryTemplate | Любой EQS-ассет с результатом точки или Actor |
| RunMode | SingleResult, RandomBest5Pct, RandomBest25Pct либо AllMatching |
| QueryParams | Именованные float/int/bool параметры запроса; имена должны совпадать с Query Params в EQS |
| ResultKey | Имя результата, по умолчанию `MovePosition` |
| ActionTimeout | Унаследованный таймаут действия; по умолчанию 10 секунд |

Для первого запроса создать Environment Query с генератором точек вокруг `EnvQueryContext_Querier`, проекцией на NavMesh и фильтром достижимости. Генераторы и тесты задаются самим EQS-ассетом: нода не знает, ищем ли укрытие, позицию для стрельбы или предмет. Для контекста противника потребуется соответствующий EQS Context; текущая нода сама цель из AIPerception в запрос не подставляет.

Цепочка: **Query → Succeeded → Move → Pause → Query**. В Components общего Behavior
добавить `NGAIQueryResultsComponent` (AI EQS Results). Через `GetClosestComponentInHierarchyUp`
получить его, вызвать `GetQueryItem(ResultKey, 0)` и передать `Item.Location` в Move:

- DestinationType = `Point`;
- Destination = `Item.Location`;
- bRelativeToPawn = `false` (результат EQS — мировая координата).

Проверить bool результата `GetQueryItem` до входа в Move; при отсутствии результата
перейти в Pause/ветку отказа, не использовать нулевой Location. Режима QueryResult
и полей QueryResultKey/QueryItemIndex у текущего NGAIMoveState нет.

`Failed` запроса/движения направить в Pause или другую ветку обработки отказа. Пустой результат, неверная конфигурация, ошибка EQS и таймаут не считаются успехом. События адресуются только машине текущего состояния, поэтому независимая оружейная FSM продолжает работать.

## Доступ к результату

Результаты хранятся в `NGAIQueryResultsComponent` родительского HFSMState по ResultKey; настройка: [BotGOAPComponents.md](BotGOAPComponents.md). На компоненте доступны `GetQueryItemCount` и `GetQueryItem` (ключ, индекс → bool и структура Location/Actor/Score). Из C++ используются те же методы. AllMatching сохраняет порядок и оценки, возвращённые EQS; одиночные режимы — выбранный движком элемент. Actor хранится слабой ссылкой и может исчезнуть; перед взаимодействием его нужно проверить.

Location — снимок позиции при завершении запроса. Move идёт к этому снимку, а не следит за Actor. EQS не меняет текущую цель памяти и не запускает движение/стрельбу автоматически. Другие состояния могут независимо использовать Actor, Location или Score.

При новом запросе прежнее значение его ключа удаляется; при отказе старые данные не используются. Успешный результат остаётся после выхода из Query, чтобы его мог прочитать следующий стейт. Он доступен только для текущего готового Pawn и его AvatarGeneration. Возраст результата автоматически не ограничен: актуальность определяет граф повторным запросом. Для параллельных запросов использовать разные ResultKey: один ключ — один источник записи.

При Exit или таймауте отменяется только принадлежащий состоянию запрос. Callback проверяет текущий запуск, Pawn и поколение Avatar. Старый ответ не публикуется в новую жизнь. Данные EQS клиентам не реплицируются; клиенты получают обычные результаты движения и боя.

## Статус проверки

API сверены с локальными исходниками UE 5.8.4; выполнен статический просмотр diff. Сборка, создание EQS-ассетов, PIE и сетевые проверки агентом не выполнялись. После сборки проверить успешный/пустой запрос, AllMatching, отмену при выходе/смерти и параллельную работу с оружейной FSM.
