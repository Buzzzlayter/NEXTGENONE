# GOAP: первый пакет

Статус: GOAP приостановлен, исполнитель и dispatcher удалены. Алгоритм и конфигурация
собраны в NGAIGOAPComponent.h/.cpp без интеграции с задачами. Актуальное состояние:
[BotGOAPExecution.md](BotGOAPExecution.md). Ниже сохранено историческое описание
эксперимента; это не инструкция подключения текущего Simple-поведения.

Реализован C++-контракт планирования, без подключения к работающему графу. Существующее поведение бота продолжает исполняться как раньше. Профиль `UNGAIPlanningProfile` назначается через Profile компонента `NGAIGOAPComponent` на HFSMState. Подключение: [BotGOAPComponents.md](BotGOAPComponents.md).

## Данные

- `FNGAIDecisionSnapshot`: известные булевы факты и именованные числовые входы оценки. Это снимок для одного решения, не владелец здоровья, патронов или позиции.
- `FNGAIFacts`: маски Known/Values. Неизвестное не удовлетворяет ни положительному, ни отрицательному предусловию. Заполнять через Set; AttackPerformed — временный факт одного цикла решения, не постоянное состояние персонажа.
- Профиль: Goals, Actions, MaxPlanDepth (12), MaxSearchNodes (512). Максимум 32 цели, 64 действия, глубина 64 и 4096 узлов. ID внутри списка уникальны; повторение одного факта в списке условий/эффектов считается ошибкой.
- Действие: Id, Preconditions, Effects, BaseCost, CostTerms. ID — команда будущему исполнителю. Плановые эффекты меняют только воображаемый мир поиска.
- Цель: Id, Eligibility, DesiredState, Priority, UtilityTerms. Уже достигнутые и недопустимые цели не выбираются.

UtilityTerms перемножают Priority на значения кривых в [0,1]. CostTerms добавляют неотрицательные значения к BaseCost. Именованные Inputs нормализованы: аргумент кривой ограничивается [0,1]. В каждой кривой нужны ключи; отсутствующий вход/пустая кривая/невалидное значение исключают соответствующую цель или действие. Пустой список terms оставляет постоянный Priority/BaseCost. Для входов и кривых нужно согласовать шкалу; SwitchMargin — абсолютная разница полезности.

## API и границы

`NGAIPlanner::SelectGoal(Profile, Snapshot, CurrentGoal, SwitchMargin)` возвращает ID. По умолчанию SwitchMargin=0.1; равная оценка сохраняет текущую допустимую цель. Возвращает None, если кандидатов нет или конфигурация невалидна. Текущая реализация не проверяет достижимость каждой цели при выборе.

`BuildPlan(Profile, Snapshot, GoalId)` возвращает упорядоченные ID действий, стоимость, количество раскрытых узлов и статус Succeeded / NoPlan / BudgetExceeded / InvalidConfiguration. Успех с пустым списком означает, что DesiredState уже выполнен. Отсутствие плана не разрешает немедленный повтор каждый Tick: ожиданием и выбором другой цели управляет будущий исполнитель.

Поиск вперёд по состояниям с нулевой эвристикой (uniform-cost, A* с h=0). Это отличается от предложенного ранее обратного поиска; выбран простой начальный алгоритм без недоказанной эвристики. Удаляются доминируемые повторы с учётом стоимости и глубины, поэтому нулевые циклы не накапливаются. Стоимости вычисляются один раз из снимка. При достижении лимита узлов поиск продолжает обработку уже созданных кандидатов: найденный план допустим, но оптимальность после отсечения не гарантируется. Глубинное/узловое отсечение без найденного плана даёт BudgetExceeded, а не доказательство невозможности.

## Пример конфигурации

Цель Attack: Eligibility HasTarget=true, DesiredState AttackPerformed=true, Priority=1.

| Action Id | Preconditions | Effects |
| --- | --- | --- |
| Equip | WeaponAvailable=true | WeaponEquipped=true |
| Reload | WeaponEquipped=true, ReserveAvailable=true, MagazineLoaded=false | MagazineLoaded=true |
| FireBurst | HasTarget=true, TargetVisible=true, WeaponEquipped=true, MagazineLoaded=true, LineOfFire=true | AttackPerformed=true |

При начальных WeaponEquipped=true, MagazineLoaded=false и известных положительных остальных условиях план будет Reload → FireBurst. Это ожидаемый пример, не фактически выполненный тест. Зарядка не расходует воображаемый резерв в этой упрощённой булевой модели: реальные количества и успешность проверит Gameplay при исполнении.

Не объявлять эффектом FireBurst гарантированную смерть цели. Не объявлять найденную EQS-точку достигнутой или безопасной без соответствующего подтверждения.
