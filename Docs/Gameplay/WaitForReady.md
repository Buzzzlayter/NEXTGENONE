# WaitForReady в UI FSM

Компонент `UNGWaitForReadyComponent` — локальное ожидание контекста игрока. Он не запускает Character FSM, не выдаёт способности и не меняет possession.

## Настройка Blueprint

1. В существующем локальном графе UI создать состояние `WaitForReady` на основе `UHFSMState` (или его Blueprint-наследника).
2. В Components добавить **Wait For Player Ready** (`UNGWaitForReadyComponent`).
3. Оставить `ReadyEvent = Ready`, `RequiredCharacterState = State.Alive` (native значение TAG_NGAlive; выбрать фактический тег Alive definition, если он другой).
4. Сделать переход `WaitForReady --Ready-->` существующее игровое состояние, в котором монтируются ActionPanel и остальной игровой UI.
5. Направить начальный переход графа в WaitForReady. Не ждать UI-готовности перед запуском самой Character FSM: она должна инициализироваться независимо.
6. Граф должен иметь контекст своего локального игрока (например, существующий HUD). Компонент не использует GetFirstPlayerController. На dedicated server он не выдаёт Ready.

Отдельный native класс состояния не нужен. Blueprint/граф пользователь настраивает вручную; агент их не создавал.

## Что проверяется

- Локальный Controller и LocalPlayer доступны.
- Текущий Pawn начал BeginPlay, его Controller и PlayerState совпадают с текущим игроком.
- Character FSM действительно вошла в требуемое состояние; все зарегистрированные resource adapters завершили вход. Pending transition не считается готовностью.
- ASC, привязанный Character FSM, принадлежит этому PlayerState и имеет текущий Pawn как Avatar; способности из активных state definitions уже доступны локально.
- HealthSet доступен, здоровье и максимум положительны; нет State.Dead.
- Инвентарь существует, у всех уже полученных entries доступны instance и item definition. Пустой инвентарь допустим.

Проверка выполняется через Tick существующего HFSM только во время ожидания. Ссылки каждый раз берутся из текущего контекста, callbacks старого Pawn отсутствуют. После успеха компонент один раз ставит Ready в очередь через существующий HFSMLibrary и прекращает проверку. Новый Enter запускает ожидание заново. Поле `WaitingFor` показывает текущую недостающую зависимость.

Это небольшой первый шаг без глобального tracker/subsystem и постоянного опроса виджетов. Событие отправляется в контекст UI FSM стандартным проектным маршрутом; не использовать одноимённый переход Ready в параллельных графах того же контекста без намерения обработать его там.

## Границы

Ready подтверждает пригодность текущего локального контекста для создания UI. Он не доказывает доставку всего серверного снимка: пустой локальный FastArray может означать и пустой контейнер, и ещё не полученный первый пакет. Поздние предметы продолжают обновлять панель через OnInventoryChanged. Backend completion, атомарная готовность всех Gameplay Effects, а также пользовательские Blueprint async-операции пока не входят в контракт.

Компонент не наблюдает потерю готовности после выхода. Смерть, disconnect и respawn должны отдельно переводить UI FSM в соответствующее состояние; для нового живого Pawn снова проходить WaitForReady. Долгоживущий глобальный flow остаётся отдельным будущим этапом.

Код статически просмотрен. Сборка, PIE и сетевые проверки агентом не выполнялись.
