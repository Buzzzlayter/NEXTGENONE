# Боты: восприятие и боевой цикл

## Параллельные машины в BP_AIBehavior_Enemy

Граф изменён через Editor MCP: существующие классы/настройки сохранены, добавлены второй FSM entry и второй Launch. Связи прочитаны обратно, неподключённые старые Stop/reroute удалены. Blueprint скомпилирован с warnings_as_errors=true и сохранён. Это проверка авторинга, не runtime: C++-изоляция событий ещё требует пользовательской сборки. PIE/сеть не запускались.

Текущая доработка разделяет существующие ноды без изменения их Implementation Class:

- `FSM` — навигация: Reposition → Pause → Reposition; при отказе Reposition — LastKnownTarget → Pause. Без известной цели оба Move дают Failed, затем пауза ограничивает повторные попытки.
- `FSM_0` — оружие: FindTarget (только видимая цель) → Equip → FireBurst. Успешная очередь возвращает к поиску, отказ очереди пробует Reload; успешная перезарядка возвращает к поиску. Отказ экипировки/перезарядки завершает оружейную машину, чтобы не создавать быстрый цикл при отсутствии оружия/патронов. Таймаут поиска повторяет поиск через reroute.
- BP Start последовательно вызывает Launch FSM и Launch FSM_0: обе машины далее исполняются независимо, это не отдельные потоки.
- Прежний общий BP Stop → событие Stop сохраняется; каждая машина имеет собственный FSM Stop и выходы Stop на её состояниях. Автоматическая невидимая остановка не добавлена.

Результаты состояний теперь адресуются только их родительской машине через native `UGCFSMState::TriggerTransitionEvent`. Рассылка Succeeded/Failed через общий Context недопустима: она переключала бы соседнюю машину. Изменение требует пользовательской сборки плагина GCFSM и NEXTGENONE с последующим перезапуском Editor. До этой сборки две машины одновременно запускать нельзя. Компиляция Blueprint не проверяет применение новой C++-логики.

Общая память выбирает цель; навигация владеет path request, FireBurst — боевым Focus и удержанием Aim. Запреты стрельбы при движении определяются существующими GAS/ALS правилами. Параллельный граф сам по себе не добавляет укрытия, тактическое планирование или гарантию достижимости.

## Владение

- `ANGAIController`: стандартный AIPerception (Sight/Hearing), команды HFSM, команды Focus и политика отношения команд.
- `UNGAIMemoryComponent` на Controller: ограниченная память наблюдений и текущая выбранная враждебная цель. Никакого сканирования всех Actor и Blackboard нет.
- Character FSM по-прежнему владеет Alive/Dead и базовыми grants. AI не создаёт предметы, не выдаёт себе оружейные способности и не пишет здоровье/боезапас.
- `FireBurst` удерживает общую Aim ability. Выстрелы идут press/release по `Input.Combat.Fire` в существующую equipment-granted ServerOnly Fire ability. Проверки GAS, источник экипировки, cooldown, расход патронов, баллистика и урон сохраняются.
- `UNGCombatComponent::GetShotOrigin()` — общий серверный якорь снаряда. AI использует его для проверки препятствия перед оружием; формула больше не дублируется в AI.

## Память и наблюдение ALS

Sight/Hearing настраиваются в AIController Blueprint через Perception / Senses Config. Native defaults: зрение 2500 см, потеря 3000 см, половина угла 80°, слух 2000 см. Значения можно менять в Blueprint; новые content paths не добавлены.

Memory defaults: обновление 0.2 с, удержание скрытого наблюдения 8 с, максимум 32 Actor, преимущество по дистанции 300 см для смены равно видимой цели. Видимая цель предпочтительнее скрытой. Сведения зрения и слуха хранятся раздельно; последняя по времени позиция используется для расследования. Текущая позиция читается только для Actor, которых Sight считает видимыми. Потеря видимости не обновляет положение сквозь стену. Уничтоженный/мёртвый Actor и Pawn с уже другим ASC Avatar исключаются.

Память очищается при потере gameplay-ready, UnPossess и EndPlay. Её время удержания независимо от очистки внутреннего кэша AIPerception; `OnTargetPerceptionForgotten` не служит источником игровой памяти. Повторный запуск состояния не очищает память.

`bObserveTarget` в Controller — галочка фонового наблюдения ALS. Видимая цель задаётся через `SetFocus`, скрытая — через `SetFocalPoint` последнего известного места. ControlRotation продолжает обрабатываться существующим ALS AnimBP. При выключении снимается фокус наблюдения. Боевой `FireBurst` отдельно владеет более высоким приоритетом Focus и снимает его при завершении: выключение фонового наблюдения не запрещает необходимое прицеливание при стрельбе.

Команда хранится и реплицируется только в `UNGTeamComponent`, созданном на PlayerState. В самом PlayerState полей/логики команды нет. Персонаж и контроллеры не реализуют командных интерфейсов и методов-переадресаций. `UNGTeamComponent::Find(Actor)` находит собственный компонент Actor либо компонент PlayerState для Pawn/Controller. `GetAttitudeTowards(Other)` определяет отношение. Отдельного NGTeams API нет. Компонент можно добавить обычному Actor; мутация разрешена только на сервере через SetTeamId.

GameMode задаёт PlayerTeamId=0 и BotTeamId=1; компонент применяет соответствующий default при серверном BeginPlay, если команда ещё не назначена. Одинаковые назначенные ID — союзники, разные — враги, отсутствие компонента или NoTeam (255) — нейтральный. Политика находится в самом компоненте; исключение bHostileToUnassignedPlayers удалено. Sight/Hearing по умолчанию воспринимают все affiliations, а Memory выбирает противников через компонент; смена команды учитывается при следующем обновлении памяти. Команда переживает замену Pawn с тем же PlayerState. Перенос состояния компонента при замене самого PlayerState/seamless travel и восстановление с backend в этот пакет не входят.

Hearing принимает штатные `ReportNoiseEvent`; проигрывание Sound/Niagara не создаёт такое событие автоматически. Шаги и выстрелы пока не подключены как источники шума. Для добавления слухового события указывать корректный Instigator; память пока учитывает только допустимых противников, а не анонимные шумовые точки.

## Ноды

FindTarget, Move, Ability и FireBurst имеют автоматические `Succeeded / Failed` и общий `ActionTimeout`. Отмена использует Failed в графе, внутренний результат Aborted сохраняется. У паузы только Succeeded. Параметры задаются до Enter. Объект поведения создаётся один раз; Controller вызывает его BP-события Start/Stop при изменении готовности. Сам граф запускается/приостанавливается в Blueprint, без Wait и NotReady.

| Implementation Class | Назначение | Начальные параметры |
| --- | --- | --- |
| `NGAIFindTargetState` | Ожидать выбранную цель из памяти | `bRequireVisible=false`, timeout 15 с |
| `NGAIAbilityState` | Экипировать реальный предмет через существующую ability | InputTag=`Input.Equipment.Equip`, HoldDuration=0, timeout 3 с |
| `NGAIMoveState` | Выбрать точку вокруг известной позиции и выполнить штатный MoveTo | DestinationType=`Reposition`, MinTargetDistance=500, MaxTargetDistance=1200, MinMoveDistance=200, AcceptanceRadius=50, timeout 10 с |
| `NGAIFireBurstState` | Удерживать Aim и выполнять ограниченную очередь | BurstDuration=1.5, AimSettleTime=0.25, AimToleranceDegrees=5, timeout 4 с |
| `NGAIAbilityState` | Перезарядка через способность оружия | InputTag=`Input.Combat.Reload`, HoldDuration=0, timeout 5 с |
| `NGAIMoveState` | Дойти до снимка последней известной позиции | DestinationType=`LastKnownTarget`, AcceptanceRadius=150, timeout 10 с |
| `NGAIPauseState` | Пауза перед следующим действием | Cooldown=1 с; только выход Succeeded, без ActionTimeout |

Все конкретные состояния — FindTarget, Move, Ability, FireBurst — непосредственно наследуют `NGAIActionState`. Варианты движения объединены в одну ноду Move с режимами `Point`, `LastKnownTarget`, `Reposition`; отдельные классы MoveToTarget/Reposition удалены. Destination/bRelativeToPawn применяются только в Point; диапазоны дистанций — только в Reposition. Режим Reposition ограничен восемью попытками проекции на NavMesh. Полный путь проверяет MoveTo с запрещённым partial path; неудача даёт Failed. Это смена позиции, а не поиск укрытия/обхода/безопасного места.

Ability и FireBurst используют обычную C++-структуру `FNGAIAbilityInput` для владения одним input/spec, таймером release и наблюдением завершения. Дополнительного UObject/компонента нет. FireBurst не наследуется от Ability и не имеет InputTag/HoldDuration: Aim фиксирован контрактом, длительность задаётся BurstDuration. Старые пользовательские значения HoldDuration у FireBurst при наличии таких нод нужно вручную перенести в BurstDuration после сборки.

FireBurst фиксирует выбранный Actor на время очереди. Потеря видимости, смена выбранного Actor, оружия, Aim или отсутствие патронов завершает действие. Перед каждым выстрелом проверяются направление контроллера, преграда от глаз и от серверного якоря снаряда. Союзник или другой блокирующий Actor на линии огня прерывает очередь. Успешный выстрел подтверждается уменьшением магазина после синхронной активации Fire; отказ уходит в Failed. Частота ограничена как таймером AI, так и прежним серверным GAS cooldown.

## Требования к настройке

Настройка контроллера, поведения и Pawn описана в [BotSetup.md](BotSetup.md). Для боя нужны реальные оружие и патроны в InitialContents, соответствующий inventory layout, grants Alive и equipment. Для навигации нужен NavMesh. AI не создаёт тестовую экипировку.

## Проверки после отдельного разрешения

Не выполнены: обнаружение и потеря LOS, срок памяти, переключение противников, дружественные цели, галочка наблюдения, экипировка/огонь/перезарядка, пустой магазин/нет резерва, препятствие перед оружием, недостижимый путь, смерть/UnPossess во время очереди, повторный possession, dedicated server и два клиента.

Нынешний цикл — явное поведение для проверки инструментов. GOAP, фракции, обмен знаниями, укрытия, EQS и координация отряда не реализованы. Reposition использует обычный горизонтальный NavMesh; произвольная гравитация и полёт не покрываются. Память можно использовать будущим планировщиком без чтения живых координат скрытых Actor и без создания второй копии здоровья/боезапаса.
