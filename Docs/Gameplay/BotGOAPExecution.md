# GOAP — приостановленный эксперимент

Основное поведение NPC сейчас настраивается в Simple с двумя параллельными FSM:
движение и работа с оружием. Развитие GOAP приостановлено.

## Изоляция кода

Весь эксперимент собран в `NGAIGOAPComponent.h/.cpp`: отражаемые типы фактов,
действий и целей, `UNGAIPlanningProfile`, снимок фактов, алгоритм поиска и сам компонент.
Имена отражаемых типов и модуль NEXTGENONE сохранены; перенос между заголовками
не меняет их `/Script/NEXTGENONE`-пути. Миграция Data Asset из-за этого переноса не требуется.

Компонент может явно вычислить план через C++ `Replan`, но не запускает задачи,
не отправляет переходы FSM, не подписывается на задачи и не хранит handles исполнения.
Алгоритм не вызывается автоматически. Чтение текущих gameplay-фактов осталось внутри
компонента; другие системы не включают его заголовок и не вызывают GOAP.

Удалены `NGAIPlanDispatchState` и `NGAIGOAPExecutionComponent`, а также отдельные файлы
Planning. Из `NGAIActionState` убраны GOAP-привязки и добавленные только для executor
события OnCompleted/OnCancelled. Сохранены обычные Succeeded/Failed, проверки жизни Pawn,
таймауты и очистка ресурсов. Общие Move, Query, FireBurst, Ability, память, EQS Results
и контекст цели продолжают использоваться независимо от GOAP.

## Что убрать в редакторе

После пользовательской сборки:

1. Назначить ботам нужное Simple-поведение вместо `BP_AIBehavior_GOAP`.
2. В экспериментальном `BP_AIBehavior_GOAP` убрать запуск GOAP-графа и ноду удалённого
   `NGAIPlanDispatchState`. Удалить сам граф, если он больше не нужен.
3. Если `AI GOAP Execution` был добавлен в Components состояний, убрать эти экземпляры.
4. Профиль `DA_GOAP_Combat` можно сохранить как данные эксперимента. Для Simple он не нужен.

Бинарные ассеты этим пакетом не изменялись. До очистки экспериментального графа
в нём возможна потерянная ссылка на удалённый native-класс; такой граф не следует запускать.
